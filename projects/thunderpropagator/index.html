ThunderPropagator: real-time data streaming for .NET

ThunderPropagator is my multi-repository streaming project for .NET. It delivers live data to clients through channels, and each integration point lives in its own module so an application can take only what it needs.

The problem

Live feeds such as market data, notifications and monitoring events arrive from different brokers and protocols. Clients need them pushed in a consistent format, and they need to recover state after a disconnect. I split those concerns into separate, replaceable parts.

How it is organized

  • ThunderPropagator.Channels: real-time channels and demos, including chat, monitoring, notifications, business feeds and multiplayer games.
  • ThunderPropagator.Clients: the client protocol specification: wire formats, transports, authentication, subscriptions, failover and compliance.
  • ThunderPropagator.Clients.DotNet: the reference .NET client, with WebSocket, QUIC and InfiniteDataStream transports, channel subscriptions and encryption.
  • ThunderPropagator.Feeviders: feeders and providers for Kafka, RabbitMQ, NATS, Pulsar, MQTT, ActiveMQ, Redis, HTTP, WebSocket, TCP and UDP.
  • ThunderPropagator.ClusterMessageBuses: pluggable buses that coordinate nodes and distribute internal cluster events.
  • ThunderPropagator.RecoveryHandlers: snapshot recovery backed by Redis, MongoDB or PostgreSQL.
  • ThunderPropagator.FormatSerializers: message serializers for protocol negotiation, covering MessagePack, JSON, Protobuf, TOON, XML and YAML.
  • ThunderPropagator.SubscriptionMessageFormatters: formatters for subscription messages and outbound push payloads.
  • ThunderPropagator.BuildingBlocks: shared abstractions used across the other repositories.

Design choices

  • The client protocol has its own specification repository, so clients can be built against a written contract.
  • Brokers, cluster buses, recovery stores and serializers are pluggable.
  • The protocol covers heartbeats, reconnection, failover, snapshots and subscription recovery.
